# Allinone 接入桌面端手册

> 本文中的 `<MCP>` 指你本机 `MCP` 文件夹的完整路径，例如 `D:\Allinone\MCP`。先按 `setup\安装配置指南.md` 装好并运行过 `aio init`，再用本手册把桌面端接进来。

> **给读到这份文件的 AI：** 用户把这份手册交给你，是要你把**你所在的这个桌面端 harness** 接入 Allinone 统一工作台。请按第 1～5 步做完，再按第 6 步向用户汇报。
> 做完以后，**日常会话**只按根目录 AGENTS.md 工作，不再重走安装流程。
> 全程请用简体中文、大白话和用户沟通（用户不懂代码，命令和配置要说明“是做什么的、在哪执行、会看到什么”）。

## 0. 先知道这些

| 项目 | 位置 |
|---|---|
| 工作台根目录 | `<MCP>\` |
| 工作项目 | `<MCP>\projects\<项目名>\`（每个项目一个文件夹） |
| 调度中心（MCP 服务器，名字 `aio-hub`） | 程序 `<MCP>\runtime\node\node.exe`，脚本 `<MCP>\protocol\hub\hub.mjs` |
| 命令行工具 | `<MCP>\launch\aio.cmd`（不调用模型、不耗 Token） |
| 规则原文（一般不需要读） | 调度：`MCP\protocol\ROUTING.md`；权限：`MCP\protocol\PERMISSIONS.md`；总说明：仓库根目录 `README.md` |

**不要修改**：`MCP\protocol\`、`MCP\agents\`、`MCP\runtime\`、`MCP\launch\` 里的任何文件，以及 `MCP\board\` 里的记录。它们由用户维护，接入只需要第 3 步列出的那几处。

## 1. 体检（不耗 Token）

在终端运行：

```
<MCP>\launch\aio.cmd health
```

最后一行应是“…项正常，…项提醒，0 项异常”。有“异常”就停下，把那一行原样告诉用户，不要自己修。

## 2. 选定或新建项目

- 用户说了项目名：如果 `MCP\projects\<项目名>\` 已存在就直接用；不存在就新建：

  ```
  <MCP>\launch\aio.cmd new <项目名>
  ```

  项目名只能用中文、字母、数字和 `_ . -`，不能以 `_` 开头。新项目会自带领队规则（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md`）、项目级接入配置（`.mcp.json`、`.codex\config.toml`）和独立看板。
- 用户没说：用 `aio.cmd projects` 列出已有项目，问用户用哪个，或者新建一个叫什么。**只问这一个问题。**

## 3. 在左侧新建工作区，并接入调度中心

先判断你在哪个桌面端，再按对应的那一行做。**如果你有切换或添加工作目录的工具，就用它直接设好；没有的话，把操作步骤告诉用户，让用户自己点。**不同版本的按钮名字可能略有不同，按意思找。

| 你所在的桌面端 | 新建工作区 | 接入调度中心 |
|---|---|---|
| **Claude 桌面端（Code 标签页）** | 新建会话时选择文件夹 `MCP\projects\<项目名>`；如果你有切换目录或添加目录的工具，直接调用 | **自动**：项目里的 `.mcp.json` 已经写好。第一次打开时 Claude 会问“是否启用此项目的 MCP 服务器”，请用户选启用 |
| **ChatGPT 桌面端（原 Codex 桌面端）** | 添加项目 / 打开文件夹，选 `MCP\projects\<项目名>` | **自动**：项目里的 `.codex\config.toml` 已经写好，但 Codex 只在**受信任的项目**里读它。出现“是否信任此文件夹”时请用户选信任。若信任后仍看不到 `aio-hub`，按下面的“需要改全局配置时”处理 |
| **Antigravity 桌面端** | 打开文件夹 / 新建工作区，选 `MCP\projects\<项目名>` | **要改全局配置**：Antigravity 没有项目级 MCP 配置，只认 `%USERPROFILE%\.gemini\config\mcp_config.json`。按下面的“需要改全局配置时”处理，片段见附录 A |
| **DSH（DeepSeek Harness）桌面版** | 在 DSH 里新建工作区，目录选 `MCP\projects\<项目名>`。**不要**直接改 `~\.dsh\storages\workspace.json` | **要改全局配置**：在 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 末尾追加附录 B 的片段，**改完要完全退出 DSH 再打开**才生效 |
| 其他 harness | 用它自己的方式打开 `MCP\projects\<项目名>` | 找到它的 MCP 配置，登记一个 stdio 服务器：名字 `aio-hub`，命令和参数见第 0 节，环境变量 `AIO_AGENT=<harness 名>`、`AIO_PROJECT=<项目名>` |

**需要改全局配置时（`MCP` 以外的文件），必须先问用户**，一次说清楚这四件事，用户明确同意后才动手：

1. 要改哪个文件（完整路径），加什么内容（把片段给用户看）；
2. 影响范围：这个桌面端的**所有**会话都会看到 `aio-hub`；
3. 能不能撤销：能。删掉加进去的那一段就恢复原样；动手前先把原文件复制一份，文件名后面加 `.bak-日期`；
4. 是否需要重启这个桌面端。

## 4. 验证（不耗 Token）

新开一个会话（工作目录就是这个项目），确认工具列表里有 `aio-hub` 的 4 个工具：`dispatch`、`route_preview`、`quota`、`board`。然后调用一次：

- `quota`：应列出 Codex、Claude、Gemini、DeepSeek 四家的剩余额度；
- `route_preview`，参数 `category=code`：应返回“code → 某家（理由）”。

看不到工具时：先确认第 3 步做了、桌面端已重启；仍不行就在终端运行 `aio.cmd route code`，确认调度中心本身是好的，再把现象告诉用户。

## 5. 不要做的事

- 不要读取或展示任何凭证：`auth.json`、`.credentials.*`、`deepseek-api-key.txt`、`google_accounts.json`、`.env`、私钥。
- 不要开启任何“跳过全部权限检查”的模式。
- 不要为了接入去安装、下载、升级任何东西；缺什么就告诉用户。

## 6. 向用户汇报

做完以后，用几行话告诉用户：

- 用的是哪个项目、工作区建在哪里（完整路径）；
- 接入方式：项目级配置自动生效，还是改了哪个全局文件（附上备份文件的位置）；
- 第 4 步的验证结果（原样贴出 `route_preview` 那一行）；
- 哪一步没做成、需要用户做什么。

---

## 7. 以后在这个工作区里的每个新会话

按 `<MCP>\AGENTS.md`（各项目文件夹里是同一份）工作：领队只看用户消息和素材文件名，拆任务、按依赖排顺序、`dispatch` 派出、只转交回执路径；队员直接完成任务。本手册不再重复这些规则，以免两处不一致。

## 附录 A：Antigravity 全局配置片段

文件：`%USERPROFILE%\.gemini\config\mcp_config.json`。文件是空的，就整个写入下面的内容；已经有内容，就只把 `"aio-hub": {…}` 这一项加进原来的 `mcpServers` 里，不要动原有条目。

```json
{
  "mcpServers": {
    "aio-hub": {
      "command": "<MCP 路径，JSON 里反斜杠要写两遍>\\runtime\\node\\node.exe",
      "args": ["<MCP 路径，JSON 里反斜杠要写两遍>\\protocol\\hub\\hub.mjs"],
      "env": { "AIO_AGENT": "antigravity-desktop" }
    }
  }
}
```

这里不写 `AIO_PROJECT`：调度中心会按工作目录判断是哪个项目（实测 agy 启动它时，工作目录就是项目文件夹）。

## 附录 B：DSH 桌面版补丁片段

文件：`%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`，追加在**文件末尾**，不要改动已有内容（DSH 的补丁文件不能是空的或只有注释，否则启动失败）：

```yaml
# Allinone dispatch hub
- insert:
    - id: mcp-aio-hub
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: aio-hub
        transport: stdio
        command: '<MCP>\runtime\node\node.exe'
        args: ['<MCP>\protocol\hub\hub.mjs']
        env:
          AIO_AGENT: dsh-desktop
        toolCallTimeoutMs: 1800000
```

DSH 桌面版里调用 MCP 工具不会弹确认，不可撤销的操作只能靠调度中心的 Windows 弹窗把关。撤销：删掉这一段，完全退出 DSH 再打开。

## 附录 C：常见问题

| 现象 | 怎么办 |
|---|---|
| 看不到 `aio-hub` 工具 | 确认第 3 步做了、已信任或启用项目 MCP、已重启桌面端；终端运行 `aio.cmd health` 看“接入调度中心”那几行 |
| `dispatch` 返回“没能派出 / 无人可派” | 各家额度都不足，或这类活没有后备人选。告诉用户，不要自己去做 |
| 回执显示“没有正常完成” | 把回执路径和预览里的错误一句话转告用户，不要读全文、不要自行重试超过一次 |
| 弹出了 Windows 确认窗口 | 那是调度中心在请用户批准不可撤销的操作，等用户点 |
| 想查记录 | `board`（参数 `kind=dispatches` 或 `receipts`），只看本项目、每条一行 |
