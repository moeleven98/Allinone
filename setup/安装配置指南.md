# Allinone 安装配置指南

> **给读到这份文件的 AI（或用户本人）：** 按第 1～8 步，在一台 Windows 电脑上把 Allinone 装好、跑通。每一步都写了“做什么、在哪执行、成功时看到什么”。
> 需要下载、登录、改 `MCP` 以外的文件时，**先告诉用户要做什么、影响什么、能否撤销，等用户同意再做**。不要替用户输入密码或密钥。
> 本文用 `<ROOT>` 表示仓库所在文件夹（例如 `D:\Allinone`），`<MCP>` 表示 `<ROOT>\MCP`。

## 0. 先确认这些

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11，有 PowerShell |
| 安装位置 | `<ROOT>` 的路径里**不能有空格和中文**（启动脚本和 agy 的钩子不支持），例如 `D:\Allinone`。**不要放在“文档”文件夹里**：实测 Windows 会拦住便携 Node 往“文档”里写文件，`aio init` 会报 EPERM |
| Git | 已安装（Codex 的部分功能要用） |
| 账号 | 想用哪家就准备哪家：ChatGPT（Codex）、Claude（Claude Code）、Google（agy / Gemini）、DeepSeek API 密钥。不必四家都有 |

目录里各部分的作用：

```
<ROOT>\
├─ MCP\              工作区（harness 只打开这里或 MCP\projects）
│  ├─ agents\<家>\bin    各家命令行程序（第 2 步装进来）
│  ├─ agents\<家>\home   各家的配置、登录、会话（只在本机，永远不要上传）
│  ├─ runtime\node       便携 Node.js（第 1 步）
│  ├─ launch\            启动脚本：codex / claude / gemini / dsh / aio / menu / quota
│  ├─ protocol\          调度中心 hub 与规则（ROUTING.md 分工、PERMISSIONS.md 权限）
│  ├─ projects\          任务项目；_template 是新项目模板
│  └─ board\             看板与回执（运行时自动生成，只在本机）
├─ setup\            安装资料（本文件、接入桌面端手册、配置模板）
└─ diagnostics\      体检与自测脚本
```

## 1. 便携 Node.js

1. 打开 <https://nodejs.org/dist/>，进入当前 LTS 版本（24.x）目录，下载 `node-v24.x.x-win-x64.zip` 和同目录的 `SHASUMS256.txt`。
2. 核对指纹：PowerShell 里运行 `Get-FileHash <zip路径> -Algorithm SHA256`，结果要和 `SHASUMS256.txt` 里这个文件那一行一致。
3. 解压，把里面那一层文件夹的**全部内容**放进 `<MCP>\runtime\node\`，使 `<MCP>\runtime\node\node.exe` 存在。

成功标志：`<MCP>\runtime\node\node.exe --version` 打印出版本号。

## 2. 安装各家命令行（都走官方渠道，装进各自的 `bin`）

不用的那一家可以跳过，但要在 `<MCP>\protocol\hub\config.json` 的 `routing.categories` 里把它从各类别的 `tiers` 中删掉，否则调度中心可能派活给它。

### Codex

1. 打开 <https://github.com/openai/codex/releases>，在最新正式版里下载 `codex-x86_64-pc-windows-msvc.exe.zip`。
2. 核对指纹：发布页每个文件旁有 `sha256:…`，与 `Get-FileHash` 结果一致。
3. 把压缩包里的**全部内容**（保持原有目录结构）解压到 `<MCP>\agents\codex\bin\`，使 `<MCP>\agents\codex\bin\codex-x86_64-pc-windows-msvc.exe` 存在。

### Claude Code

官方安装脚本不能改安装位置，用 winget 的官方包：

```
winget install --id Anthropic.ClaudeCode --exact --source winget --location <MCP>\agents\claude\bin
```

成功后 `<MCP>\agents\claude\bin\claude.exe` 存在。winget 可能把这个目录加进用户 PATH；如果只想通过启动脚本使用，可以把那一项从用户 PATH 删掉（这是系统设置，先问用户）。

### agy（Antigravity CLI，用 Gemini）

官方安装脚本支持指定目录（在 PowerShell 里运行）：

```
& ([scriptblock]::Create((irm https://antigravity.google/cli/install.ps1))) --dir <MCP>\agents\gemini\bin --skip-path --skip-aliases
```

成功后 `<MCP>\agents\gemini\bin\agy.exe` 存在。安装过程会在 `%LOCALAPPDATA%\antigravity\staging\` 暂存一份 `agy.exe`，可以手动删掉。

### DSH（DeepSeek Harness）

用第 1 步的便携 Node 和 npm 官方仓库安装：

```
cmd /c "call <MCP>\launch\_env.cmd && npm install --prefix <MCP>\agents\deepseek\bin @deepseek-ai/dsh"
```

npm 11 默认不运行包的安装脚本，会提示有几个包的脚本没运行；实测 DSH 不需要它们，不用批准。成功标志：`<MCP>\launch\dsh.cmd --version` 打印版本号。

## 3. 初始化：填入本机路径、放好配置模板

```
<MCP>\launch\aio.cmd init
```

它会：把规则文件和接入配置里的 `{{MCP}}` 占位符换成你的真实路径；把 `setup\templates\agents\` 里的配置模板复制进各家的 `home`（已存在的不覆盖）。模板包括：Codex 的权限、沙箱和 hub 登记；Codex 的不可撤销命令规则；Claude 的权限和守门钩子；agy 的权限、守门钩子和 hub 登记。

## 4. 登录

每一家只在自己的窗口里登录，凭证留在各自的 `home` 里（agy 例外，见下）。

| 家 | 怎么登录 |
|---|---|
| Codex | 运行 `<MCP>\launch\codex.cmd login`，按提示用 ChatGPT 账号登录 |
| Claude Code | 双击 `<MCP>\launch\claude.cmd`，按提示用 Claude 账号登录 |
| agy | 双击 `<MCP>\launch\gemini.cmd`，按提示用 Google 账号登录。它的令牌存在 Windows 凭据管理器里，不在 `home` 中 |
| DeepSeek | 在 `<MCP>\agents\deepseek\home\` 新建 `deepseek-api-key.txt`，只写一行 API 密钥 |

## 5. DSH 领队接入（不用 DSH 当领队可跳过）

1. 运行一次 `<MCP>\launch\dsh.cmd web --help`，让 DSH 建好 web 配置。
2. 把 `setup\templates\dsh-web-patch.yml` 的内容（`{{MCP}}` 换成你的路径，用正斜杠）追加到 `<MCP>\agents\deepseek\home\profiles\web\cordis.patch.yml` 末尾。

## 6. 启动器：自带的和自己加的

`<MCP>\launch\` 里的每个脚本都先调用 `_env.cmd`（把便携 Node 放到 PATH 最前面，npm 缓存留在 `runtime\`），再把这一家的配置目录指到 `agents\<家>\home`，最后进入 `projects\` 启动程序。所以它们不会读写你用户目录下各家的原有配置。

想加一个新的 harness：

1. 把程序装进 `<MCP>\agents\<名字>\bin\`。
2. 照 `codex.cmd` 写一个 `<名字>.cmd`：`call "%~dp0_env.cmd"` → 设置该程序认的配置目录环境变量（指向 `agents\<名字>\home`）→ `cd /d "%AIO_MCP%\projects"` → 运行程序。**`.cmd` 文件里只能用英文字符**，否则 `chcp 65001` 之后 cmd 会解析错乱。
3. 想让它当领队：在它的 MCP 配置里登记 stdio 服务器 `aio-hub`，命令 `<MCP>\runtime\node\node.exe`，参数 `<MCP>\protocol\hub\hub.mjs`，环境变量 `AIO_AGENT=<名字>`。
4. 想让它当队员（被派活）：在 `protocol\hub\config.json` 的 `agents` 里加一项（`command`、`args`、`env`、`parser`），并在 `routing.categories` 里把它放进合适的类别。`parser` 目前有 `codex`、`claude`、`gemini`、`deepseek` 四种输出格式；新程序的输出格式不同时，要在 `protocol\hub\hub.mjs` 的 `PARSERS` 里加一个。

## 7. 验证（都不耗 Token）

| 运行 | 成功时看到 |
|---|---|
| `<ROOT>\diagnostics\health.cmd` | 最后一行“…项正常，…项提醒，0 项异常” |
| `<ROOT>\diagnostics\selftest.cmd` | “结果：96 通过，0 失败”（用假队员测试，不调用模型） |
| `<MCP>\launch\aio.cmd quota` | 已登录的各家剩余额度 |
| `<MCP>\launch\aio.cmd route code` | “code → 某家（理由）” |

## 8. 开始使用

- 让任意已接入的 harness 把工作目录设在 `<MCP>\projects`（项目里已带 Claude 的 `.mcp.json` 和 Codex 的 `.codex\config.toml`；第一次打开时，按提示启用或信任）。
- 直接给任务：领队按 `AGENTS.md` 只拆任务、派活、转交回执路径；成品在 `projects\<项目名>\outputs\`。
- 把桌面端（Claude、ChatGPT/Codex、Antigravity、DSH 桌面版）接进来当领队：见 `setup\接入桌面端.md`。

## 常见问题

| 现象 | 原因和处理 |
|---|---|
| Codex 执行命令报 `CreateProcessWithLogonW failed: 5` | Codex 0.164 的管理员版沙箱在部分机器上启动不了（openai/codex#9062）。模板默认已改用 `unelevated`；新版本可试着改回 `elevated` |
| agy 报“invalid UTF-8” | 钩子命令里的路径带了引号或空格。`<ROOT>` 不能有空格，`hooks.json` 里的路径不要加引号 |
| 双击 `.cmd` 一闪而过或出现乱码命令 | `.cmd` 文件里有中文字符；只能用英文 |
| `dispatch` 返回“无人可派” | 该类别的各家都额度不足或没装；用 `aio quota` 查看 |

## 隐私提醒

`MCP\agents\*\home`、`MCP\board`、`MCP\projects\<你的项目>`、`MCP\runtime` 里是你的登录凭证、会话记录、任务内容和程序本体，仓库自带的 `.gitignore` 已经排除它们。**不要强行把它们加进 Git。**
