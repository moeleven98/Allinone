# 权限协议 v0.3（2026-10-24）

## 本次生成任务授权

用户明确授权普通任务、图片、TTS、视频直接执行，正常调用所选服务和提交任务所需材料不重复询问，不以“本机未验证”为批准门槛。队员使用受限写入模式执行，不再统一只读或仅规划；不开放跳过所有权限检查。

生图单次申请超过 5 张（imageCount 含所有变体）或全工作台滚动一分钟超过 5 次 dispatch 生图申请时，由中心请求批准；第 5 张、第 5 次不触发。计数全项目共享，使用跨进程锁；一次批准仅覆盖一次 dispatch。拒绝也记录为一次申请，自动额度重试不重复计数。队员不得扩大批次，新申请交回领队。此计数覆盖 AIO 派发，无法观察队员内部或绕过 AIO 的直接服务调用。

日常任务不执行 health、自查或接入验证。只在接入新模型/新客户端时按 `.Allinone\setup` 中的手册检查一次；用户明确要求诊断时另行执行（自检程序在 `.Allinone\diagnostics`）。这两个文件夹在工作区以外，工作中的 harness 不会读到。

每次 dispatch（包括指定队员）重新查询全部四家额度，在项目 quota-reads.jsonl 留下查询编号、时间、来源和状态。Codex 使用 account/rateLimits/read；Claude 使用其本地登录的订阅额度接口；Gemini 每次执行 agy /usage；DeepSeek 查余额。查询失败显示未知，不用旧数据补齐。Claude 订阅接口随客户端变化，令牌过期或接口拒绝会显示未知。

以下不可撤销操作规则继续有效；其中“上传第三方”不包括已经授权的生成服务输入。宿主可独立要求审核，本地工具提示不能取消宿主规则。

## 总原则：默认放权，只拦不可撤销

> **用户授权的范围远大于限制的范围。**
> 凡是做错了还能撤回的操作，一律直接执行，不需要用户批准；
> **只有做了就撤不回来的操作，才需要用户批准。**
>
> 判断标准只有一条：**这件事做错了，能不能恢复到做之前的样子？** 能 → 直接做；不能 → 先申请。
> 拿不准的，按“不能撤销”处理。

本协议适用于 `.Allinone` 体系内的所有 harness（Claude Code、Codex、agy、dsh）、调度中心和扩展模块。

> v0.1（“覆写、删除、调用第三方进程都要申请”）已作废。用户 2026-10-24 明确要求：放权远大于限权，只有不可撤销的操作才需要批准。

## 1. 直接执行，不用批准（放权范围）

| 类别 | 包括 | 为什么可以放权 |
|---|---|---|
| 读取 | 读取本机任何目录和文件、搜索、列目录 | 只读，不改变任何东西 |
| 新建 | 新建文件、文件夹 | 删掉就恢复原样 |
| 修改 / 覆盖 | 修改已有文件 | 调度中心会先把原文件备份到回收站，随时能还原 |
| 删除 / 移动 / 重命名 | 走调度中心的文件工具 | 先进回收站，随时能还原 |
| 运行程序 | 运行命令、脚本、编译、测试 | 第 2 节列出的不可撤销命令除外 |
| 派活 | 把子任务派给其他 agent 的 CLI | 只是让另一个 agent 干活，本身不造成不可撤销的后果 |
| 下载、安装 | 下载文件、在 `.Allinone` 里安装软件和依赖 | 可以卸载或删除 |
| 调用扩展 | TTS、STT、本地视频模型等 | 产出写在扩展自己的 `output\` 里 |
| 联网读取 | 打开网页、查资料、调用只读接口 | 不对外留下任何东西 |
| 订阅额度 | 用掉 ChatGPT Plus、Claude Pro、Gemini Pro 的额度 | 额度会按周期自动恢复 |

## 2. 必须批准（不可撤销的操作）

| 类别 | 例子 | 为什么撤不回来 |
|---|---|---|
| **永久删除** | 不经回收站的删除（`rm -rf`、`del`、`Remove-Item`、`rmdir /s`、`format`）；清空回收站；删除大到回收站放不下的文件 | 删了就没有备份 |
| **对外发出** | 发送邮件、消息、评论；发帖、发布、部署；提交网页表单；上传到第三方；`git push` | 别人已经收到或看到，收不回来 |
| **改写历史** | `git push --force`、`git reset --hard` 丢弃未提交内容、`git clean`、改写已共享的提交 | 原来的内容被抹掉 |
| **花钱** | 按量计费的调用（DeepSeek API 等）超出预算；购买、付款、订阅 | 钱花出去就退不回来 |
| **凭证与账号** | 修改密码、生成或吊销密钥和令牌、退出登录、修改账号设置 | 旧凭证作废后，依赖它的东西都会断 |
| **系统级改动** | 系统和用户环境变量（PATH 等）、注册表、系统服务、防火墙、用户账户、安全设置、驱动 | 不在回收站的保护范围内，很难完整还原 |
| **泄露风险** | 读取并发送登录凭证、私钥、`.env`、浏览器用户数据 | 内容一旦发到云端模型或外部，就收不回来 |
| **数据库破坏性操作** | `DROP`、`TRUNCATE`、没有条件的 `DELETE` / `UPDATE` | 没有自动备份 |

**按量计费预算**：每天 **10 元人民币**，超出部分逐次申请（2026-10-24 用户确认采用 v0.2）。
DeepSeek 的定位：**只做顶班**。绝大部分工作由 ChatGPT Plus、Claude Pro、Gemini Pro 三个订阅分担，DeepSeek 只在某家订阅额度不足时补上，所以正常情况下花不了多少钱；这条预算是兜底的安全线。
花费的算法：调度中心在每次派活前后各查一次 DeepSeek 余额，用两次的差额作为花费。余额只精确到 0.01 元，极小的调用会记成 0 元，所以记录到的花费会略微偏少。

## 3. 一律禁止

开启任何“跳过全部检查”的模式：`--dangerously-skip-permissions`、`bypassPermissions`、`--dangerously-bypass-approvals-and-sandbox`、`danger-full-access`。

原因不是限权，而是这些模式会连第 2 节那几项“撤不回来”的操作一起放行，等于把唯一要守的门拆掉。

## 4. 回收站（让“删除和覆盖”变成可以撤销）

- 通过调度中心修改、覆盖、删除、移动文件之前，原文件会先复制到 `MCP\board\trash\<日期>\`，并记下原来的位置。
- 保留 **30 天**；清空回收站属于第 2 节的“永久删除”，需要批准。
- **注意**：各家 harness 自带的删除和覆盖工具不经过调度中心，**没有这层备份**。所以：
  - 各家原生工具改文件可以放权（大多数 harness 自己也有撤销或检查点功能，但不保证）；
  - 各家原生工具执行第 2 节里的永久删除命令，要设为“询问”。

> 2026-10-24 补充：为了节省领队的上下文，调度中心的 `fs_*`、回收站、`proc_run` 工具默认**不再提供给领队**，只给脚本（`aio`）用。领队自己改文件时走的是 harness 自带的工具，没有回收站备份；不可撤销的命令仍由各家的守门设置把关（见第 6 节）。如果要让领队也用带回收站的文件工具，在 `protocol\hub\config.json` 的 `leaderTools` 里加上它们。

## 5. 批准怎么弹

- 由调度中心自己弹出 Windows 确认窗口，写清楚谁要做什么、影响哪些内容、为什么撤不回来；用户点“是”才执行。
- 一次批准只对这一次操作有效。
- 所有批准和拒绝都记在 `board\approvals.jsonl`；所有放权执行的操作也记在 `board\actions.jsonl`，方便事后追查和还原。

## 6. 落到各家 harness 的设置（2026-10-24 已实施）

Claude 和 agy 共用一个守门脚本 `protocol\hub\guard.mjs`，它读取的不可撤销命令清单和调度中心是同一份（`protocol\hub\config.json`），所以两边的判断标准完全一致。

| 家 | 实际配置 | 效果 |
|---|---|---|
| Claude Code | `agents\claude\home\settings.json`：`defaultMode=acceptEdits`；`allow` 放开 Bash、PowerShell、编辑、读写、联网、`mcp__aio-hub`；`additionalDirectories` 加入 用户目录（`%USERPROFILE%`）；工具调用前钩子 `guard.mjs --for claude` | 日常操作不弹窗；不可撤销命令（会认出 `dir; Remove-Item` 这种藏在前缀后面的写法）弹 Claude 自己的确认；被派活时允许普通执行和写入，仍检查不可撤销命令 |
| Codex | `agents\codex\home\config.toml`：`approval_policy="on-request"`，`sandbox_mode="workspace-write"`，可写范围 用户目录（`%USERPROFILE%`），联网打开，沙箱暂用非管理员版（`[windows] sandbox="unelevated"`，因为 Codex 0.164 的管理员版在本机启动不了，详见 README）；命令规则文件 `agents\codex\home\rules\allinone.rules`（17 条，`prompt`） | 用户目录内随便写；`git push`、`rm`、`Remove-Item`、`gh pr create` 等需要确认，`gh pr list`、`git status` 等不拦。**局限**：规则按命令开头的词匹配，像 `powershell.exe -Command "Remove-Item …"` 这样包一层的写法识别不出来，这种情况只能靠沙箱的可写范围兜底 |
| agy | `agents\gemini\home\.gemini\antigravity-cli\settings.json`：`permissions.allow` = `read_file(*)`、`write_file(*)`、`command(*)`；`agents\gemini\home\.gemini\config\hooks.json`：工具调用前钩子 `guard.mjs --for agy` | 日常操作不弹窗；不可撤销命令设为 `force_ask`（每次都问）；被派活时允许普通执行和写入，仍检查不可撤销命令 |
| dsh | 网页界面（领队）用默认的 `workspace-write`；派活（队员）用 `DSH_PERMISSION_MODE=workspace-write` | dsh 调用 MCP 工具时不会弹确认，第 2 节的事只能靠调度中心的弹窗把关 |

注意：钩子命令里的路径**不能加引号**。agy 用 `cmd /c` 执行钩子，带引号会被拆坏，cmd 再输出一段 GBK 编码的报错，agy 就会报“无效的 UTF-8”。我们的路径里没有空格，所以不加引号也能正常运行。

**能做到的边界（如实说明）**：第 2 节是按命令和工具名识别的。harness 自带的命令行可以用各种写法绕开识别，比如把删除命令写进一个脚本再运行。这一层只能挡住常见写法，挡不住所有写法。完全可靠的把关只存在于调度中心自己的工具里。
